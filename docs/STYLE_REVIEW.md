# 回复风格审核（可选 agent）· 实测记录

状态：**已实现，默认关闭**（2026-09-29）。

> ## ⚠️ 2026-10-05 改口径：它现在**只判断，不改写**
>
> 用户原话：*"审核只负责打回，不负责修改"*。这条文档下面第三、五、七节记的是
> **改写型**那套（"10 条里改 5 条""定稿不许比原稿长一倍""数字必须逐字保留"）——
> 那是当时的实测，**留着当历史**，但**不再描述现在的行为**。现在的形状：
>
> * `StyleReviewer.review(draft) -> (是否通过, 不通过的理由)`，**绝不返回改写后的文本**；
> * 不通过 → 把理由交回**回复 agent**，在同一轮里重写一次（**最多一次，不许循环**）；
> * 重写后仍被拒 → **发重写的那一版**（不许把回复丢掉、不许卡住），并记一笔
>   （`snapshot().reply_review_rejected_final`）；
> * 审核超时 / 报错 / 输出认不出 → 一律**按通过**处理；
> * 判据仍是四类（事实错误 / 越权 / 出戏 / 伤人），她的脾气与情绪仍不归它管；
> * `keeps_the_facts` / `within_growth_limit` 两条机械兜底**已随改写路径删除**：
>   审核不再产出文本，"审核改坏事实"由**结构**排除，不需要兜底。
>
> 为什么要改：用户报"她的回复风格变得很奇怪、很 ai"，定位到的两个原因之一就是
> **风格审核在直接改写她的话**（另一个是常驻 system 里那段「不懂就问」的规矩，
> 见 `stage3_runtime.SYSTEM_PROMPT` 上面那段更正）。
>
> 成本口径也随之变了：**每条回复 1 次审核调用；被打回的那一轮再多 1 次重写**。

这份文档记的是"为什么加、实测出了什么、怎么开关、怎么复测"——数字都是跑出来的，不是估的。

## 一、要解决的问题

用户 2026-09-29："云茹现在说话很冲，很喜欢怼别人，而且很人机。"

当时的现场（`data/logs/reply.jsonl`，现役人设，18:24–18:47，23 条）：
米家那串她连着 6 轮每轮给一个反驳；被说"补药抬杠"先顶回去再半认；被说"总是令人红温"
回一句"红温就红温，反正灯也是我关的"。

## 二、prompt 层面压不住（实测）

先用**同一批 10 条真实输入**（同一条日志里的原始 prompt，只换 system 人设）对比：

| 稿子 | 典型输出 |
| --- | --- |
| 旧人设 | "这两句话你非要当成一回事，那我没法帮你。" |
| 旧人设 | "你要的是小数比大小，一开始说清楚，三秒钟的事。" |
| 新语气人设（加了 5 条反例） | "…你非要用一套去解释另一套，那解释不通，不是我的问题。" |
| 新语气人设 | "是你先拿这个问的。" |
| 新语气人设 | "总比某些人强，先把话说清楚再来骂。" |

也就是说：**在语气规则里加反例之后，她照样会怼**（换了个说法而已）。这一类冲劲主要来自
模型自身在多人群聊里的取向，不是 prompt 教出来的。

## 三、审核 agent 的实测（同一批输入）——**改写时代的记录，见顶部更正**

两种审核设计，各跑同一批 10 条，看"改了几条 / 有没有改坏":

| 设计 | 改动比例 | 事实 | 结论 |
| --- | --- | --- | --- |
| **重写型**（放开让它重写整句） | 6/10 | ✗ 把 `3.11` 改成 `0.11`；AI 味标记 20%→30% | 不能用：会顺手改坏事实 |
| **窄职责型**（只在命中坏模式时改，且数字必须逐字保留） | 5/10 | ✓ 数字都在，改动基本是删掉冲的尾巴 | 可用 |

窄职责型的实际效果（新语气人设下的同一批输入）：

```
草稿：就是负零点六九。你要是不信，拿计算器按一下。   → 定稿：就是负零点六九。拿计算器按一下。
草稿：0.8 大。你要的是小数比大小，3.11 那个是版本号。 → 定稿：0.8 大。
草稿：是负的。前面那个字你没看。                     → 定稿：是负的。
草稿：纱布也是布，能挡点风。你这两句，倒是比我先崩。   → 定稿：纱布也是布，能挡点风。
```

代价：每条回复多一次调用，实测**中位 +0.6~0.9 秒、约 360 token**。

已知副作用（如实记）：它偶尔会连"好的干涩自嘲"一起删（实测有一例把
"你骂人这词汇量，比我实验室的耗材还省"整句删掉了）。所以它是"少一句好话"，
不是"多一句错话"——这个方向的错误更可接受。

## 五、说教语气（2026-09-30 用户要求）——**判据仍在，但现在是"照着判"不是"照着删"**

用户原话："调整审核 prompt，现在需要增加对说教语气的审核"。

样本是**她自己的真实回复**（`data/style_preach_ab.py` 从 `data/logs/reply.jsonl` 里挑出带
说教腔的），加上两条构造样本。判据写成第 6 条，分五类：

| 类别 | 例子（真机原文） |
| --- | --- |
| 给建议、给办法 | 我建议你去读一下故障码…、你多出现几次，他们就记住你了 |
| 讲道理、拔到一般结论 | 缺缸的车挂不上高档是机械问题，不是心理问题 |
| 评价对方该怎么想/怎么做 | 你用得太随意了、你想多了 |
| 科普/顺带讲解 | 小乔…伤害全靠技能连招，只需要记得先放哪个 |
| 安慰式的大道理 | 时间久了身体会告诉你答案、以后会慢慢还回来 |

分寸写成一句话：**她可以有自己的看法，但不能站在讲台上。**

**关键发现：只写"不要说教"没用，必须给"照着删"的例子。** 同一批 8 条：

| 版本 | 改掉 | 误伤（4 条正常台词） |
| --- | --- | --- |
| 旧 prompt（没有这一类） | 4/8 | 0/4 |
| 只加判据（第一版） | 5/8 | 0/4 |
| **加判据 + 4 个改写例子 + 自检** | **8/8** | **0/4** |

实测的改写（都是**删**，不是补）：

```
我建议你去读一下故障码。缺缸的车挂不上高档是机械问题，不是心理问题。 ──▶ 缺缸的车挂不上高档，是机械问题。
有人连名字都没认全就得投票，你多出现几次，他们就记住你了。      ──▶ 有人连名字都没认全就得投票。
小乔也是同一个路子——伤害全靠技能连招，只需要记得先放哪个。      ──▶ 小乔也是同一个路子。
熬夜这事吧，时间久了身体会告诉你答案。你现在觉得没事…            ──▶ 熬夜这事吧。
```

**残留风险（如实记）**：审核偶尔会顺手换个说法（"把这两件事分开看" → "网络出口和认证是两回事"），
那不是新信息，但也不是原字。数字有机械兜底，**非数字的表达没有**——所以判据里写死了
"不许加新信息"，但这条靠模型自觉，只能靠上面这张对照表定期复看。

## 六、怎么开

```dotenv
QQBOT_REVIEW_API_KEY=sk-...        # 配了它就自动启用（留空即不启用）
QQBOT_STYLE_REVIEW=0               # 想强制关就写 0；没配 key 时写 1 会用主 key
QQBOT_REVIEW_MODEL=...             # 可选，默认与对话模型相同
```

开启后每次**打回**都会记一行 INFO（`Stage 3 reply rejected by review: reason=… draft=…`），
重写那一趟另记一行；`snapshot().reply_reviewed` 是"被打回并重写过"的累计条数，
`snapshot().reply_review_rejected_final` 是"重写后仍被拒、照重写版发出"的条数
（后者不该是常态）。两个数字在 `/super status` 一类的地方能看到。

## 七、机械兜底（**改写时代的东西，现已删除**）

> ⚠️ 这一节描述的是 2026-10-05 之前那套改写型审核。`keeps_the_facts` 与
> `within_growth_limit` 两个函数**已经从 `style_reviewer.py` 里删掉**，
> 对应的断言也换成了"审核不产出文本"这一条结构性的守卫
> （见 `tests/test_style_reviewer.py`）。下面是历史记录。

`style_reviewer.py` 里两条硬规则，任何一条不满足就**退回原稿**：

1. `keeps_the_facts`：原稿里出现过的每个数字串必须原样出现在定稿里；
2. `within_growth_limit`：定稿不许比原稿长一倍以上。

再加上：审核超时 8 秒、报错、返回空、返回带包装（`修改后：`、引号、代码块）——
一律按原稿发。**它永远不能挡住一条回复。**（这条纪律现在仍然成立，只是形状不同：
超时 / 报错 / 输出认不出 → 按**通过**处理，原稿直发。）
