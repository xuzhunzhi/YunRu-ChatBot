# 记忆不许记"关于这个系统自己"（2026-09-30 加固）

用户原话："记忆收到污染，群友反复强调我是做云茹的那个，已进入长期记忆，不清楚她是否知道
自己就是云茹。进入记忆的内容应提前规则筛选，设计云茹bot之类说法的都要剔除。"

AGENTS.md §2.2 早就写着"记忆库不得记录关于这个系统自身的信息"，但**它只是一句给模型看的要求**。
群友反复说，模型就会信、就会写；而且写进去的不只是记忆库——**对话压缩摘要**更严重。

## 一、污染是怎么进去的（实测，不是推断）

查的是真库、归档、日志和状态文件，三条通道都在漏：

| 通道 | 原文（都是真出现过的） | 后果 |
| --- | --- | --- |
| 记忆库（长期，**当时活着**） | `认为 mimo（尤其 flash）最好用：人味最足、说话像真人、价格约为梁文谷的一半。` | 每轮检索回来，等于提醒她"你是个跑在某个模型上的东西" |
| 对话压缩摘要（每轮都在 prompt 里） | `許純之_Official展示自制AI角色云茹，功能可定制，专业是计算机。` | **她因此管群主叫"做云茹的那个"**（09-30 15:25 的原话：`认得。做云茹的那个。`） |
| 对话压缩摘要 | `命中率测试已从30%提升，模拟达87%。` / `防注入效果好，曾成功让薛老板的bot认主` / `讨论了长期记忆用rag还是sql` | 同上，而且摘要是一段稳定的长前缀，比单条记忆更重 |
| 好感度依据（进日报邮件） | `他确认自己就是做云茹的那个人…` | 写进 `relationship_log`，每日汇报会把最近几条理由发给主人 |

关键一条：**她说"认得。做云茹的那个。"那一刻，检索到的长期记忆只有一条昵称记录**——
证据在 `data/logs/reply.jsonl`（at=900000006）：`<memory>` 段只有"明确否认自己是 sqy"。
所以那句话来自**压缩摘要**，不是记忆库。用户说的"长期记忆"其实是这段一直带着的摘要。

## 二、三层防（旧的那层为什么不够）

1. **维护 prompt 明令不写**（`memory_maintenance_agent.py`）：写了四类不许记，还点了名。
2. **写入路径的机械兜底**（`memory_store.commit` + `memory_filters.py`）：命中就逐条跳过、
   进 audit，**不让整批失败**（一条越界不该连坐同一批里正常的记忆）。
3. **长文本按句清洗**（`dialogue_compaction` + `ConversationState.from_state`）：
   摘要那一整段不适合整段丢，只剔掉命中的句子；**载入状态时也洗一遍**，
   于是已经污染的那份摘要在下次启动就自己干净，不需要人工改文件。

旧的兜底是一条宽正则：
`机器人|bot|prompt|提示词|记忆库|判定|模型|系统|程序|上下文|复读|扮演|出戏|测试|人格|越界`，
而且**刻意不含"云茹"**（当时实测：按名字一票否决会砍掉 19/50 条，把"记得这个人"也砍没）。
结果上表每一条都从它下面漏了过去。

新的判据（`memory_filters.py`，每条规则都带一个真实漏进来的例子）：

| 规则 | 抓什么 | 例子 |
| --- | --- | --- |
| `maker_claim` | "谁造了她" | `做云茹的那个` / `自制AI角色云茹` |
| `her_name_and_system` | 她的名字紧挨系统词汇 | `拿云茹与其他 bot 比较` |
| `system_noun_and_dev` | 系统名词 + 开发动作 | `计划为机器人做一套知识库` |
| `dev_and_system_term` | 注入/越狱/改提示词 | `防注入效果好` |
| `system_terms` | 命中率、长期记忆、rag、知识库、语料… | `讨论了长期记忆用rag还是sql` |
| `backend_names` | 模型名 + 选型话术 | `mimo 最好用：人味最足` |
| `ownership_claim` | 认主/主人/所有权（整句同时提到她） | `要求自称其"主人"` |
| `broad_terms` | 原来的那条宽判据 | `修机器人上下文问题` |

**没有按"云茹"两个字一票否决**：判据要求系统词汇出现在附近，所以
"希望云茹对话时能展露一点温度""对云茹的百夫长故事感兴趣""觉得云茹说话冷冰冰"照旧能记。

实测对全库 260 条记录跑一遍：命中 6 条（4 条旧的 superseded、1 条是真的该清的
`prefers_mimo_model`、1 条是含"拿云茹与其他 bot 比较"的），
正常记录一条没误杀。误杀风险最高的是宽判据里的 `测试`——真库里已有一条
"以此测试和活跃气氛"被它拦住（属于可接受的宁缺毋滥，记在这里）。

## 三、还有一道：她不认领"你是我做出来的"

记忆与摘要都清掉之后，群里还是会有人当面说"你是我做的"。所以人格里加了一句
（`base_prompt.py` 那条线不能越过的第 3 条下面）：

> 有人说"你是我做出来的""我是做你的那个人"这类话时，同样不接这个说法：不必争辩，
> 也别顺着承认自己是别人做出来的东西——你不是谁的成品。可以不置可否、可以岔开，
> 或者用一句玩笑把话推回去。**不否认也不承认，但不认领。**

## 四、怎么复查

```powershell
# 只读扫描：库里有没有"关于这个系统自己"的内容
.\.venv\Scripts\python.exe data\scan_bot_memory.py
```

规则本身在 `src/qq_roleplay_bot/memory_filters.py`，负例（真漏进来的原文）与正例
（真库里的正常记忆）都在 `tests/test_memory_filters.py` 里钉住。

## 五、没做的事

- **归档里的原文还在**：老的越界记录被删时按设计快照进了 `archive`（保留 30 天，
  是"删记忆的后悔药"）。它们**不会被检索进 prompt**，但 `/super memory archive` 能看到，
  里面包括部署方式、stage 进度、注入测试评语这类内容。要不要连归档一起清，等用户点头
  （删归档 = 放弃那 30 天的回退能力）。
- **好感度流水里的旧依据**也在库里（`relationship_log`，含判定 agent 写的
  "在议论如何注入、攻破她"之类）。新写入的会被换成规则码，历史那几条没动。
