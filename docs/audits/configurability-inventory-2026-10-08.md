## 一句话结论

**现在写死、但明显应该可调的值至少 20 处；而这 20 处里没有一处能改在面板上。**

原因是两条结构性事实（都是实测）：

1. **面板白名单没有数值类键。** `operator_config.SETTINGS` 一共 30 个键，`kind` 只有
   `bool` / `str` / `csv` / `secret` 四种，**没有 number**。也就是说面板能开能关、能填
   地址与 key，但**任何一个数字都改不了**。
2. **`dev_config` 是 import 期求值。** 它的常量在模块导入时算一次，所以"改环境变量"
   只在下次启动生效——这是"需重启"的默认形态。而这个仓库里**唯一能热更数值的机制**
   是少数几个函数式读法（`persona_offset_hours()`、`reply_api_base_url()` 等，见
   `dev_config.py:294-297`）与 `runtime_flags` / `operator_config` 这十个布尔开关；
   数值没有这待遇。

于是现状只能落到两档：**写死 ✗** 或 **环境变量 ✓（需重启）**。

## 不建议做成可调的 5 条

1. **数据边界短码的长度与字符集**（`data_boundary.py:71-73`，7 位 / `A-Z2-9` / `‹›`）——形状判据（含入站中和）与它绑在同一份正则上，改了就等于同时改"判违规"和"防伪造"两件事。
2. **`SUPER_ADMIN_USER_IDS` / `ADMIN_USER_IDS` 的兜底号**（`dev_config.py:267-268`）——已经出过一次"文件被 checkout 还原导致超管权限丢失"的事故，这类名单只该走 `.env`，不该给任何在线入口。

## 要真正做成可调，最小改动是什么

1. **给 `operator_config` 加 number 类型的键。**
   现在 `SETTINGS` 的 `kind` 只有 `bool` / `str` / `csv` / `secret`，`normalize()`
   （`operator_config.py:112-136`）没有数值分支。加一种 `kind: "number"`（并让
   `webui_data.mask_settings` 之外的渲染路径认识它），才谈得上"面板能改数字"。

2. **数值一律"调用时现读"。**
   `dev_config.X` 是 import 期求值，照抄它的常量读法会让面板上的改动**不生效**。
   已有的正确形状可以照抄：`dev_config.py:294-297` 的 `persona_offset_hours()`、
   `:212-233` 的 `reply_api_*`，以及 `memory_config.py` 的 `_float_env` / `_int_env`
   ——都是"调用时读环境"，所以改配置不必重启。

3. **带上下限钳制。**
   这个仓库已经有现成范式，照着写即可：`memory_config.py:41-42`
   （间隔夹 [60, 86400]、保留期夹 [1, 30]）、`conversation_context.py:51`
   （历史条数夹 [1, 100]）、`feature_log.py` 与 `chat_log.py` 的容量夹取
   （[10, 1000000]，**不允许无限增长**）。没有钳制的数值项等于给了一条把 bot 拖死的路。

4. **写清"面板显示已生效但实际没生效"这个坑怎么避免。**
   `operator_config.SETTINGS` 每一项都要如实标 `applies`：`live`（改完下次调用就读到）
   还是 `restart`（落盘了但要重启）。现在那条纪律已经写在 `operator_config.py:36-39`
   与 `runtime_flags.py:1-15` 里。数值项接进来时必须二选一并照实标：
   - 走 `live` 的，调用点必须现读（见第 2 点），并有一条测试钉住"改了立刻生效"；
   - 走 `restart` 的，面板必须显式提示"需重启"，**不许假装已生效**。
