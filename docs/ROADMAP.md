## 一、当前"思维链"的实际形状（这是"太简单"这句话的基线）

一条消息走到她开口，最多经过这些调用：

| 顺序 | 谁 | 干什么 | 一次调用？ |
| --- | --- | --- | --- |
| 0 | 识图（可选） | 有图的消息先换成一句描述 | 1 次（只对有图的消息） |
| 1 | 判定 agent | 要不要接、在聊什么、话题起点 | 1 次（小 prompt，无人设） |
| 2 | 回复 agent | 写得说什么、怎么分段、引用谁 | 1 次（人设 + 记忆 + 知识 + 关系 + 画像） |
| 3 | 风格审核（可选） | 狭窄校对：删掉"冲"的尾巴 | 1 次（只在要回时） |

另有几条**独立**的链路：记忆维护（每 10 分钟一批）、对话压缩（攒满才跑）、
每日写信（草稿 → 事实校对两阶段）、读信回信（走 0–3 那条）。

**结论（实测支撑）**：现在的"链"是**判定 → 回复 →（可选）审核**，中间没有显式推理、
没有自我检查循环、没有主动取资料的动作。判定与回复各自只输出结论，看不到"想过什么"。

## 三、下一版：复杂思维链（用户 2026-09-30 定：本版本迭代完就做）

前提是**先量再改**（这个仓库已经吃过两次"改完指标好看但问题还在"的教训：
语气那次 AI 味标记降了、用户要的"不冲"没解决；审核 agent 那次第一版还会改坏事实）。
所以下一版每加一层，都要有"同一批真实输入的前后对照 + 延迟与 token 成本"。

候选方向（按"收益 / 代价"排，不是按炫技排）：

| # | 方案 | 具体做法 | 主要代价 |
| --- | --- | --- | --- |
| 1 | **换更强模型做对照** | 判定/回复各跑一遍 `deepseek-v4-pro` 与现在的 `deepseek-chat`，同一批真实输入比风格、事实、延迟、token | 钱与延迟；先做**一次对照实验**就能知道值不值 |
| 2 | **显式思考字段** | 回复 agent 先写 `<think>`（不发出）再写 `<reply>`；可测"有 think / 无 think"的差异 | 输出 token 变多；要保证 think 绝不外泄 |
| 3 | **多步判定** | 把"要不要接"拆成：值不值得接 → 接谁的话 → 接什么 → 用什么语气（每步一个中间字段，仍是一次调用） | prompt 变长；中间字段要可观测 |
| 4 | **检查-重写循环** | 现有窄职责审核升级成"改完再检查"，最多 N 轮 | 延迟 ×N；实测第一版审核有过度删减 |
| 5 | **主动取资料（agentic）** | 她能自己决定"去查记忆/知识库/邮件"，而不是全靠被动注入 | 需要多轮工具调用；**不能放宽 DATA 边界** |
| 6 | **多候选 + 评分** | 生成 3 条候选，用一个评分 agent 选最好的 | 成本 ×3~4；要证明比单条好 |
| 7 | **主动目标/日记** | 她在群里主动推进某个话题（有长期目标），而不是每轮独立反应 | 属于"人格与主动性"，风险最高，放最后 |

**要有对照的东西**（沿用已有的测量工具）：
`data/reply_tone_audit.py`（标记率）、`data/reply_replay.py`（同批输入重放）、
`data/style_reviewer_ab.py`（审核前后对照）、`data/day_audit.py`（跑一天之后的体检）。

**边界不变**（AGENTS 2.1/2.2/2.3）：system 前缀只装人格与规则；所有外部内容走 DATA；
不加机制词进她的 prompt；普通命令走插件；共用 `runtime.serve`，不复制主循环。
