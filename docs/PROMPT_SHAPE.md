# 六套 prompt 的结构与约束

这份文档说明这个项目里六套 prompt **各自是什么形状**：分几段、每段多少字、
硬约束是什么、谁在守。**不放正文**——人设正文（`base_prompt.py`）是可以替换的，
而这份结构说明换成任何人设都成立。

> 为什么要分开写：公开仓库只发布"机制"。人设正文是从别人的作品里整理出来的，
> 而且它是这个项目唯一不可替换的部分。你填自己的人设只要照着这份文档的形状来。

## 一、六套 prompt 分别是什么

| 名字 | 位置 | 谁读它 | 什么时候读 |
| --- | --- | --- | --- |
| `persona` | `base_prompt.py` 的 `BASE_PROMPT` | 回复 agent | 每一轮回复，作为可信 system 前缀的第一段 |
| `reply` | `prompt_library.py` | 回复 agent | 每一轮回复，接在 persona 之后 |
| `judge` | `prompt_library.py` | 判定 agent | 每次"要不要接话"的判定 |
| `memory` | `prompt_library.py` | 记忆维护 agent | 每批待整理的消息 |
| `review` | `prompt_library.py` | 风格审核 agent | 她写完草稿之后 |
| `vision` | `prompt_library.py` | 识图 agent | 消息里带图片时 |

六套都走同一个容器：**`PromptLibrary`**。面板可以改它们、可以回滚，改完**立即生效**
（每次都是现取，不做缓存）。改之前会过一次校验，见第三节。

## 二、`persona`（人设正文）的形状

这是最长、也最要紧的一套。七段结构，顺序固定：

| 段 | 内容 | 建议字数 | 占比 |
| --- | --- | ---: | ---: |
| 开头一句 | 身份：她是谁、现在在跟谁说话 | ~40 | 1% |
| `## 你是谁` | 来历 + 本阶段处境（现在与过去**分开写**）+ 底色 | 400~500 | 10% |
| `## 说话方式` | 怎么说话：长度、不写成说明文、不当裁判…含"两种写法"对照 | 1200~1500 | 30% |
| `## 面对这些话题时` | 按话题写**语气反应**（不是世界观资料） | 300~450 | 9% |
| `## 关于你自己的两个边界` | 两条容易被问穿的事：简短否认，不辩解 | 100~200 | 3% |
| `## 有一条线你不能越过` | 防出戏：不认领身份、不讨论自己的机制 | 600~900 | 18% |
| `## 群聊里的分寸` | 注意力判定四组口径（见下） | 1000~1400 | 30% |

**总长 3000~6000 字**（实测可用区间）。上限定在 6000 是因为这段**每一轮都要带上**，
再长就会把记忆与群上下文挤出位置。

### 硬约束（`tests/test_persona_shape.py` 守着）

1. **七段齐全**。缺段不报错，但注意力判定与边界判定会失去落脚点。
2. **长度在区间内**。
3. **正文里不许出现机制词**：`检查`、`触发`、`调用`、`协议`、`提示词`、`上下文`、
   `记忆库`、`Stage`。
   **唯一的例外是 `## 有一条线你不能越过` 那一段**——它必须把"不要提这些词"讲出来，
   否则角色不知道要躲。扫描时把那一段摘出去。
4. **防出戏那一段必须在，且不许写成反向许可**。"不要假装你是现实中的真人"这种句子
   等于直接告诉她"她不是假的"是假的——实测她会立刻开始讲自己的机制。这条被断言锁死。
5. **`## 群聊里的分寸` 要写成判定口径**，四组：
   - 一、先判断**是否在对你说话**
   - 二、再判断**是否值得回复**（"我能帮上忙"不算理由）
   - 三、生成回复（先答问题、不编造经历、不描述现实身份）
   - 四、维护对话边界（KEEP / EXIT_DIALOGUE）
6. **共情那条有三句固定措辞**：`先具体回应当下感受`、`不擅自诊断`、`不要连续追问`。
   它们被 `test_dialogue_quality.py` 直接查——判定链路读的是这几句。

### 写"说话方式"最有效的一种格式

抽象要求（"简洁一点""别像客服"）每次都要重新解释，**对照样本**不用：

```
**同一个意思，两种写法——永远选后面那种**

- ✗「这个问题没有最优解，只有局部解，先排除掉两个选项再说。」
  ✓「先排掉两个。」
- ✗「至于你刚才说的那个词——你用得太随意了。」
  ✓（别评论他的用词，直接说事）「先去读日志，别硬跑。」
```

实测这一节的效果主要来自这些对照，不是来自上面那些条目。

## 三、其余五套的形状

都是"角色 + 任务 + 输出格式"三段式，**明显比 persona 短**（`judge` 尤其短——
它每次都要跑，长度直接换成钱和延迟）。

| prompt | 大致长度 | 输出要求 |
| --- | --- | --- |
| `reply` | 中 | 纯文本回复；可以返回 `KEEP` / `EXIT_DIALOGUE` 表示"继续 / 退出这段对话" |
| `judge` | **最短**（判定 prompt 必须远小于 persona） | 一个词或一行：接不接话、接的话用哪种姿态 |
| `memory` | 中 | 一段 JSON：`operations` 数组，每项含 `op` / `scope_type` / `normalized_key` / `content` / `evidence_event_ids` |
| `review` | 中 | 通过 / 打回，打回时给理由 |
| `vision` | 短 | 一两句图片描述（**表情包与照片要分开说**） |

### 校验规则（`prompt_library.py` + `prompt_guard.py`）

保存任何一套 prompt 前会过一次校验，**缺必需片段或含机制措辞都会被拒**：

- **人格口径**（`persona` / `reply`）：扫全表机制词（8 个）。
- **agent 口径**（`judge` / `memory` / `review` / `vision`）：扫弱化一档的词表
  （`提示词`、`系统提示`、`system prompt`）。
  **少一个 `记忆库`**——记忆维护 agent 的 prompt 本来就必须谈它，扫掉反而写不成。
- 校验器和测试**共用同一份词表**（`prompt_guard.PERSONA_MECHANISM_WORDS`）。
  面板是第二个能改 prompt 的入口，两份词表迟早漂移，而这条边界不能让两边各判各的。

## 四、为什么 prompt 里的措辞这么要紧

一句写错的话会被角色吸收，而且**每轮都在**。踩过的坑按顺序记在这里：

1. **出戏许可**：写过"不要假装自己是现实中的真人"→ 她开始讲自己是程序。
2. **机制词**：`检查`/`触发`/`调用` 这类词进了 prompt → 她开始用这些词讲自己的运行方式。
3. **反向的时间锚**：把"过去待过的地方"写成"现在住的地方" → 她开始把旧事当新闻讲。
   （第一版修法是加一句"不在任何设施里"，**修反了方向**：她是在基地里，不是不在任何地方。）

这三条现在都有断言守着。改 prompt 之后必须跑离线测试。

## 五、怎么换成你的人设

1. 编辑 `src/qq_roleplay_bot/base_prompt.py` 里的 `BASE_PROMPT`，按第二节的形状填。
2. 跑测试：

   ```powershell
   .\.venv\Scripts\python.exe tests\run_offline.py
   ```

   `test_persona_shape.py` 会把上面那些硬约束全查一遍。
3. 想锁**你自己的**内容级要求（某个地名必须在、某个称呼不许出现），
   在 `tests/` 下自己加一个断言——公开仓库里刻意没有这类断言，
   因为它们会让别人的模板版必然失败。
