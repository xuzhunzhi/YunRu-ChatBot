## ① 不懂就问（她现在不懂装懂）

### 现状诊断（实测，不是猜）

```
base_prompt.py:160      "明确 @、点名、直接提问或承接她上一句时，优先考虑参与。"
dialogue_judge.py:248   "相处分寸只用来决定'没被叫到时要不要插话'。**被叫到时它没有否决权**"
JudgeVerdict（dialogue_judge.py:137）的字段只有：
    should_reply / topic / topic_start / related / lore / guard_up / guard_reason
    → **没有任何字段表示"她懂不懂"**（`related` 是"相不相关"，不是"懂不懂"）
```

**结论**：被叫到就必须接，而且没有任何信号能让她选择"问"，所以她只能硬接。

### 用户举的三个例子

> 综测、电赛、谷歌手机

这三样的共同点**不是"她不知道"**，而是"**她知道一点点，够填满一句话，不够说对**"——
**能生成听起来合理的话**，这才是"不懂装懂"最坏的形状（空白反而安全）。

### 设计

1. **判定加字段** `understood`（判定本来就是那趟"便宜调用"，多问它一句"看明白了吗"最省）。
2. **核心加确定性的"根据检查"**（模型"觉得自己懂"不能绕过它）：

   | 话题类型 | 主动插话的要求 |
   | --- | --- |
   | 日常 / 情感 / 闲聊 / 她自己的事 | 照旧，可主动插 |
   | 具体的专业·事实·圈内话题 | 要求**至少一处根据**：知识库命中 / 记忆命中 / 语境明确 |
   | 三样都没有 | **不许主动断言**：只能问，或转成她自己的角度 |

3. **被叫到也允许以"问"回应**（即把"被叫到时没有否决权"保留原意——不冷落人——但**开口子**：
   回应可以是问）。
4. **限量**（否则她会每句都问）：同一话题最多一次；10 分钟内最多 3 次。
5. **人格三条禁令**（写成性格，不许出现机制词）：
   * 把对方的话换个说法复述一遍，当成自己懂了；
   * 说"这个我知道 / 我懂"——除非真能说出一个具体细节；
   * 编具体细节（数字、流程、型号）来撑场面。

### 测试

* `understood=unsure/lost` + 被叫到 → 走"问"，**不是断言**；
* 同上但没被叫到 → **不插话**；
* 问的频率被限住；
* 禁令措辞存在且**不含机制词**（照 `tests/test_persona_shape.py` 的做法）；
* 不回归：`understood` 默认 True，正常话题照旧回答。

### 落地（2026-10-04）——与上面设计的差别，逐条写清

| 设计里的说法 | 实际落地 | 为什么 |
| --- | --- | --- |
| 判定加字段 `understood` | `JudgeVerdict.understood`（`clear`/`unsure`/`lost`）+ `JudgeVerdict.specialist`，另有 `verdict.unsure` | "专业·事实话题"这个门也要判定来给，不然核心没法只凭消息正文判断 |
| 人格三条禁令 | 三条禁令写进 **`ask_when_unsure.UNSURE_ASK_RULE`**，由 `stage3_runtime.compose_system_prompt` 拼进回复 prompt | 生产上 `BASE_PROMPT` 整段来自真人格文件（`base_prompt.py:249-251`），写进人格等于只在 `dev/` 生效。`tests/test_ask_when_unsure.py::test_the_rule_survives_a_replaced_persona` 拿假人格钉住这条 |
| 限量（同一话题一次、10 分钟 3 次） | `dev_config.ASK_MAX_PER_TOPIC` / `ASK_MAX_PER_WINDOW` / `ASK_WINDOW_SECONDS`（`QQBOT_ASK_*`）+ 运行期开关 `ask_when_unsure` | 照既有配置写法，不硬编码 |
| 根据检查（知识库 / 记忆 / 语境） | `ask_when_unsure.decide_grounding`（纯函数）+ `context_is_explicit` | 第三样"语境明确"是**粗判据**：只认"挂在眼前某一句上"与"对方正在解释这件事"；判不准就当作不明确（宁可问，不许编） |
| 没被叫到且没懂 → 不插话 | 在取资料**之前**就返回，不额外翻知识库 | 这一轮本来就不出声，翻资料白花钱 |

1916 字到 2121 字（`tests/test_dialogue_judge.py` 要求它小于回复 prompt 的三分之一）。
**不多花一次调用**：那两个信号由原本那趟判定顺带吐出。

## ② 问 → 解释 → 词条（"黑话"就是它的第一个受益者）

### 闭环

```
① 她看不懂（谐音梗 / 综测电赛这类圈内话 / 没有根据的话题）
② 她当场问一句（见 ①；限量）
③ 群里有人解释（"就是XX的意思"）——真实、就地、带上下文
④ 抓取那条解释 → 存成词条（**存原句证据，不存模型给的定义**）
⑤ 下次命中就注入（进 DATA 区、限量、没命中一个字都不拼）
        ↳ 若她理解错了 → 群里会纠正她 → 又回到 ①
```

### 用户定的两条

1. **谁的解释算数 = 模型自行判定**，依据是判定**已经在吃**的 `stance`（相处分寸）
   + 记忆里的**人物画像**。实测：`dialogue_judge.py:183` `stance=None`、
   `:250` `stance.as_judge_hint()` ✓（**注**：`亲密度/提防度` 这两个名字在代码里搜不到，
   别按这两个词去找；`/super affinity|profile` 在这条分支上也不存在）。
   → 所以抓取时必须**记下是谁说的**，好让判定能把人和画像对上。
2. **被逗了 → 主动调起巡检查验**。识破形状（确定性模式匹配，不靠模型猜）：
   `还真信了 / 被骗了 / 逗你的 / 这是假的 / 笑死 / 你居然信 / 上当了`
   → 往**巡检**那条路派一个查验任务（巡检是现成的：`focus.py:158`"20 条巡检"、
   `stage3_main.py:3001/3035/3089`）→ 巡检结果三选一：保留 / 更正 / 撤销。
3. **被逗之后只记事件**（用户明确："只记事件"，**不自动降谁的可信度**——
   怎么影响判断是画像和模型的事，核心不该替他定死）。

### 可靠性来自三条确定性规则（不是人审批）

| 规则 | 门槛 | 作用 |
| --- | --- | --- |
| 够格才生效 | 出现 ≥3 次、来自 ≥2 个人、不在已知词表里 | 挡掉一次性怪词与瞎猜 |
| **只给证据，不给定义** | 自动附最近 2–3 条原句（带谁说的） | 没有"模型编的含义"可错 |
| 会过期 | 30 天不再出现降级、60 天清掉 | 黑话会过时，词表不烂 |

**为什么这样能兼顾"自维护"与"可靠"**：不可信的那一段（发现/猜测）**恰好是不生效的那一段**；
生效靠的是群里真人的解释 + 确定性门槛 + 随时能 `/super slang no` 撤掉。

### 人工只在例外时出现

```
平时：不管（自动生效、自动过期）
出事：/super slang no 尊嘟假嘟      ← 一句话撤掉
想看：/super slang list / why 2     ← 看现状与证据
```

**不需要面板，也不需要每天开 CLI**——`/super` 就是 Stage 3 自己的命令系统，手机上就能发。
（面板将来可以做同一个词库的另一个界面，但**没有它功能一点不少**。）

## ③ 情绪（她太"三无"了）

用户原话：**"可以表达情绪，只要不是怼人就行"**。

### 三个方案

| | 做法 | 成本 | 风险 |
| --- | --- | --- | --- |
| **A（已完成，`45f3535`）** | 人格审计：把 prompt 里压制情绪的约束改掉，加明确的"情绪许可 + 不许怼人" | 0 | 可能不够 |

| **C（不建议）** | 独立"情绪 agent" | 每条 **+1 次调用** | 多一个漂移源，容易长出与人格平行的东西 |

### B 的关键约束

* 心情**只影响分寸与措辞**，不影响事实与安全规则；
* 心情状态**不进 system 前缀**（走 DATA）；
* 会产生**衰减**、有上下限；
* 与已有的 `stance` 分工：`stance` 是"对这个人的长期分寸"，心情是"对当下这一刻"。

### A 的审计范围（嫌疑度排序）

1. **`style_reviewer.py` + `prompt_library.py` 里风格审核那套**——每条回复发送前过一道校对，
   写得保守就会把情绪磨平（改成"保留语气与情绪，只挡：事实错误、越权、出戏、伤人"）；
2. `base_prompt.py`（**上半是"写 prompt 的说明"、下半才是人格正文**，别改错地方）；
3. `stage3_runtime.py`（80 处"不要/不必/不许/别"，只改压制情绪的）；
4. 一条容易误判要保留的：`base_prompt.py:68`"不当裁判、不纠正别人"——它压的是**纠正别人**，
   不是**表达情绪**。
