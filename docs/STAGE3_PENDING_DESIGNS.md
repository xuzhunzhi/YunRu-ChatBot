## ① 不懂就问（她现在不懂装懂）

### 现状诊断（实测，不是猜）

```
base_prompt.py:160      "明确 @、点名、直接提问或承接她上一句时，优先考虑参与。"
dialogue_judge.py:248   "相处分寸只用来决定'没被叫到时要不要插话'。**被叫到时它没有否决权**"
JudgeVerdict（dialogue_judge.py:137）的字段只有：
    should_reply / topic / topic_start / related / lore / guard_up / guard_reason
    → **没有任何字段表示"她懂不懂"**（`related` 是"相不相关"，不是"懂不懂"）
```

**结论**：被叫到就必须接，而且没有任何信号能让她选择"问"，所以她只能硬接。

### 用户举的三个例子

> 综测、电赛、谷歌手机

这三样的共同点**不是"她不知道"**，而是"**她知道一点点，够填满一句话，不够说对**"——
**能生成听起来合理的话**，这才是"不懂装懂"最坏的形状（空白反而安全）。

### 设计

1. **判定加字段** `understood`（判定本来就是那趟"便宜调用"，多问它一句"看明白了吗"最省）。
2. **核心加确定性的"根据检查"**（模型"觉得自己懂"不能绕过它）：

   | 话题类型 | 主动插话的要求 |
   | --- | --- |
   | 日常 / 情感 / 闲聊 / 她自己的事 | 照旧，可主动插 |
   | 具体的专业·事实·圈内话题 | 要求**至少一处根据**：知识库命中 / 记忆命中 / 语境明确 |
   | 三样都没有 | **不许主动断言**：只能问，或转成她自己的角度 |

3. **被叫到也允许以"问"回应**（即把"被叫到时没有否决权"保留原意——不冷落人——但**开口子**：
   回应可以是问）。
4. **限量**（否则她会每句都问）：同一话题最多一次；10 分钟内最多 3 次。
5. **人格三条禁令**（写成性格，不许出现机制词）：
   * 把对方的话换个说法复述一遍，当成自己懂了；
   * 说"这个我知道 / 我懂"——除非真能说出一个具体细节；
   * 编具体细节（数字、流程、型号）来撑场面。

### 测试

* `understood=unsure/lost` + 被叫到 → 走"问"，**不是断言**；
* 同上但没被叫到 → **不插话**；
* 问的频率被限住；
* 禁令措辞存在且**不含机制词**（照 `tests/test_persona_shape.py` 的做法）；
* 不回归：`understood` 默认 True，正常话题照旧回答。

### ⚠️ 2026-10-05 晚：**"问"这条路整个拆掉了**（口径改成"要么不出声，要么别断言"）

**用户原话**：*"别做不懂就问"* · *"先改掉**不懂装懂硬插话**"*，并给了判据——
**"没根据的时候，要么不出声，要么别断言"**。所以上面那一套里关于"以问回应"的部分
**全部作废**（不是"暂时不用"，是这条路不该存在）。

| 上面写过的 | 现在（2026-10-05 晚起） |
| --- | --- |
| 被叫到 + 没懂 → **以"问"回应** | 被叫到 + 没懂 + 话里有具体断言 + 三处没根据 → **打回，让她在同一轮里重写一次**（`NO_ASSERT_NOTE`：能说的照说、不知道就直说，**不是**反问她） |
| 没被叫到 + 没懂 → 不插话 | **不变**，而且加了新信号：没被叫到 + 没懂 + **具体话题** → 不出声 |
| 限量（同一话题最多问一次、10 分钟 3 次）+ `QQBOT_ASK_*` | **整套删掉**：`dev_config` 里那三个键、`dev_config.ASK_MAX_*` / `ASK_WINDOW_SECONDS` 都没了——没有消费者了。`AskBudget` 这个类留在 `ask_when_unsure.py` 里（它的语义仍有测试钉着），但**引擎不再持有它**，也不再传 `ask_budget=` |
| `ASK_TURN_NOTE` / `HOLD_TURN_NOTE` 进易变段 | **没有调用点**了（留着当历史与文字来源，测试仍扫它们的机制词）。引擎的 `clarify_note` **恒为空串** |
| 反馈："要么只在那一轮的易变段出现，要么由核心确定性拦" | 这一版**两条都做到**：唯一递到她眼前的是 `NO_ASSERT_NOTE`（只在她被打回的那一轮、经 `_revision_request` 进 user 段）；路由与打回由 `decide_grounding` / `has_specific_claim` **确定性**决定，一个字都不进 prompt |

**这一版新增的确定性判据**（`ask_when_unsure.has_specific_claim`）：
她那一版话里有没有**具体断言**——数字（阿拉伯/汉字+量词）、型号/编号、流程词。
刻意收窄，判错的一侧是"少打回一次"而不是"凭空打回正常聊天"：
句子里有"不清楚/不知道/记不清/没把握"这类**承认不知道**的写法，或者整句是**反问**，
就不算断言。

**两条边界的实测结论**（`dev/` 分支 `main`，2026-10-05 晚）：

* 被叫到、但**只说自己的角度**（"这个我没跟上，不敢乱说。"）→ **放行**，不打回；
* 有根据（知识库 / 记忆 / 语境任一处命中）→ **一个字都不拦**（三种各有一条用例）；
* 风格审核与"别断言"**共用同一次重写机会**（审核已经打回重写过就不再打回第二次）。

**上一版的两个教训（这一版都没有重犯）**：① 常驻 system 里**没有**任何新增的行为指导
（`UNSURE_ASK_RULE` 与 `NO_ASSERT_NOTE` 都不在 `compose_system_prompt` 的那条路上，
守卫见 `tests/test_ask_when_unsure.py`）；② 不靠提示措辞自觉——真正的拦与放行是
`decide_grounding` 与 `has_specific_claim` 两个纯函数加一处引擎判断。

## ② 问 → 解释 → 词条（"黑话"就是它的第一个受益者）

> **2026-10-06 部分落地**：入口改成**纯被动**（用户否掉了"问"），
> 词条库 + `/super slang` + 面板接缝已在本体（`dev/`）里；
> **检索/注入本轮不做**。与下面设计稿的差别逐条写在**本节末**"落地"那一段。

### 闭环

```
① 她看不懂（谐音梗 / 综测电赛这类圈内话 / 没有根据的话题）
② 她当场问一句（见 ①；限量）
③ 群里有人解释（"就是XX的意思"）——真实、就地、带上下文
④ 抓取那条解释 → 存成词条（**存原句证据，不存模型给的定义**）
⑤ 下次命中就注入（进 DATA 区、限量、没命中一个字都不拼）
        ↳ 若她理解错了 → 群里会纠正她 → 又回到 ①
```

### 用户定的两条

1. **谁的解释算数 = 模型自行判定**，依据是判定**已经在吃**的 `stance`（相处分寸）
   + 记忆里的**人物画像**。实测：`dialogue_judge.py:183` `stance=None`、
   `:250` `stance.as_judge_hint()` ✓（**注**：`亲密度/提防度` 这两个名字在代码里搜不到，
   别按这两个词去找；`/super affinity|profile` 在这条分支上也不存在）。
   → 所以抓取时必须**记下是谁说的**，好让判定能把人和画像对上。
2. **被逗了 → 主动调起巡检查验**。识破形状（确定性模式匹配，不靠模型猜）：
   `还真信了 / 被骗了 / 逗你的 / 这是假的 / 笑死 / 你居然信 / 上当了`
   → 往**巡检**那条路派一个查验任务（巡检是现成的：`focus.py:158`"20 条巡检"、
   `stage3_main.py:3001/3035/3089`）→ 巡检结果三选一：保留 / 更正 / 撤销。
3. **被逗之后只记事件**（用户明确："只记事件"，**不自动降谁的可信度**——
   怎么影响判断是画像和模型的事，核心不该替他定死）。

### 可靠性来自三条确定性规则（不是人审批）

| 规则 | 门槛 | 作用 |
| --- | --- | --- |
| 够格才生效 | 出现 ≥3 次、来自 ≥2 个人、不在已知词表里 | 挡掉一次性怪词与瞎猜 |
| **只给证据，不给定义** | 自动附最近 2–3 条原句（带谁说的） | 没有"模型编的含义"可错 |
| 会过期 | 30 天不再出现降级、60 天清掉 | 黑话会过时，词表不烂 |

**为什么这样能兼顾"自维护"与"可靠"**：不可信的那一段（发现/猜测）**恰好是不生效的那一段**；
生效靠的是群里真人的解释 + 确定性门槛 + 随时能 `/super slang no` 撤掉。

### 人工只在例外时出现

```
平时：不管（自动生效、自动过期）
出事：/super slang no 尊嘟假嘟      ← 一句话撤掉
想看：/super slang list / why 2     ← 看现状与证据
```

**不需要面板，也不需要每天开 CLI**——`/super` 就是 Stage 3 自己的命令系统，手机上就能发。
（面板现在也有这个界面了：左栏「知识库 → 黑话」，见下表的"面板的界面"那一行；
但**没有它功能一点不少**——`/super slang` 仍然是完整的那一份。）

用户这一轮的口径是：*"金句我看应该划到**知识库**里"*、*"还有**黑话**"*，

| 设计稿 | 落地成什么 | 为什么 |
| --- | --- | --- |

| ⑤ 下次命中就注入 | **本轮不做**（用户："等我看过效果再说"） | 会动对话路径。这一轮只到"记下来、看得见、改得动" |
| `/super slang no/list/why` | `/super slang [list\|all\|why\|set\|del\|wrong\|ok] …` | 与 `/super quote` 同一形状（列 + 改 + 删） |
| 面板的界面（**已做**，2026-10-06 插件线） | `UiSeams.learned`（7 个函数：金句读/改/停用笔记、黑话读/改/删/标错）；面板上是左栏**「知识库 → 金句 / 黑话」两个子项** | 面板只能调装配点注入的闭包；**接缝里没有记忆入口、也没有对话入口**（有测试逐个钉住字段名）。面板那两个页面只请求 `/api/knowledge/quotes\|slang`，**不读 `data/` 下的文件**（静态断言钉住；路由侧对着真 `QuoteStore`/`SlangStore` 核过形状） |

**判解释句的漏与误报（实测，2026-10-06）**：

- **误报**：靠三道护栏挡——词的左侧必须是边界（句首/空白/标点）、词里不许出现
  `的了是在不这那…` 这类句子零件、整句像问句（`？` / 句末"吗" / "是不是"）就跳过。
  实测"他说的就是对的""这个字幕好像只能识别""这不就是摆烂吗"都不记。
- **漏**（已知，宁可漏也不误报）：单字黑话（"典就是经典"——词长下限 2 字）、
  词前面挂着修饰语的长句（"昨天那个综测就是综合测评"）、以及不在这 10 种句式里的解释
  （"你们说的那个词，其实是……"）。
- 这两条都写进了 `slang_learning` 的模块说明，改动它们要连测试一起改。

## ③ 情绪（她太"三无"了）

用户原话：**"可以表达情绪，只要不是怼人就行"**。

### 三个方案

| | 做法 | 成本 | 风险 |
| --- | --- | --- | --- |
| **A（已完成，`45f3535`）** | 人格审计：把 prompt 里压制情绪的约束改掉，加明确的"情绪许可 + 不许怼人" | 0 | 可能不够 |
| **B（推荐后续）** | A + 判定那趟顺带吐"心情微调" + 核心维护有界心情状态 → 当背景给她 | **0 额外调用** | 要写好衰减与边界 |
| **C（不建议）** | 独立"情绪 agent" | 每条 **+1 次调用** | 多一个漂移源，容易长出与人格平行的东西 |

### B 的关键约束

* 心情**只影响分寸与措辞**，不影响事实与安全规则；
* 心情状态**不进 system 前缀**（走 DATA）；
* 会产生**衰减**、有上下限；
* 与已有的 `stance` 分工：`stance` 是"对这个人的长期分寸"，心情是"对当下这一刻"。

### A 的审计范围（嫌疑度排序）

### ⚠️ 2026-10-05 更正：审核**只判不改**了，"情绪"这一半的判据仍是四类

用户原话：*"审核只负责打回，不负责修改"*。此前它是**改写型**（`review()` 返回改完的文本），
也就是**风格审核在直接改写她的话**——用户报的"她的回复风格变得很奇怪、很 ai"里，
这是被定位到的第二个原因（第一个见 §① 的 2026-10-05 更正）。

现在：`review(draft) -> (是否通过, 理由)`；判不过 → 理由交回**回复 agent**，同一轮里重写一次
（**最多一次**）；重写后仍被拒 → **发重写的那一版**并记一笔；超时/报错/输出认不出 → 按**通过**。
四类判据一个字没动（事实错误 / 越权 / 出戏 / 伤人），"她的脾气与情绪不归它管"那几句也留着，
只是把"只改这四类"改成"只看这四类"。`keeps_the_facts` / `within_growth_limit` 两条机械兜底
**随改写路径一起删掉**：审核不再产出文本，"改坏事实"由结构排除，不需要兜底。

守卫跟着改口径（守的东西没变）：`tests/test_persona_shape.py` 里
`test_review_prompt_keeps_emotion_and_only_blocks_four_kinds` 的锚点从"只改这四类/
写得冲也不改/一字不差/改完不许比原稿更冷更淡"换成"只看这四类/写得冲也不算越界/
只判断不改写/一律判过"；`tests/test_style_reviewer.py` 里新增
"打回 → 同一轮重写一次""重写仍被拒也照发""审核返回改写文本时不听它的"三条。
**第 2026-10-04 那条突变（删掉"只改这四类"）现在没有对象了**——那个说法已经不在 prompt 里，
